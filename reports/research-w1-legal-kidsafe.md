# PRJ-016 W1 リサーチレポート: 法務・kid-safe 運用ガイドライン v1

- **作成日**: 2026-04-26
- **作成部署**: リサーチ部門
- **担当タスク**: W1 TASK-D
- **対象**: 13 歳未満保護者同意 / 改正個情法 / COPPA / UNICEF / AI 安全ポリシー / アプリ内法務文言の v1 確立

---

## エグゼクティブサマリー

1. **改正個人情報保護法（令和8年改正）**: **16 歳未満を本人とする場合、原則として法定代理人（保護者）の同意を必須化** する方向で 2026 年通常国会（1/23-6/21）に提出予定[^1][^2][^3]。本案件は **16 歳未満** を対象とするため、Phase 1 から **保護者メール認証 + 同意ログ + 撤回権 + 削除権** を実装する。
2. **COPPA 2025 改正**: FTC が 2025-04-22 に公表、**コンプライアンス期限 2026-04-22**[^4][^5]。本案件は当面国内 β なので直接適用外だが、**永続識別子 / 生体情報 / 位置情報 / 行動推論データ を「個人情報」に追加** + 新 3 種の同意確認手段（SMS / KBA / 顔認証 ID 比較）が将来の海外展開時に必須。
3. **UNICEF AI for Children v3（2025-12 発行）**: 10 要件のうち本案件最重要は **保護者通知 / 危機検知 / プライバシー by design / AI 透明性**[^6]。Phase 0 既出 6 要件に加え **「AI が物理的・心理的危害から子どもを守る（CSAM・unsafe AI companion 対応）」** が新項目として強調。
4. **AI チャット安全ポリシー（Phase 0 強化版）**: System Prompt の必須要素 9 項目 + 危機検知ワード 60 語（日 40 + 英 20）+ エスカレーション 3 系統（189 / 24時間子どもSOS 0120-0-78310 / 児童相談所相談専用 0120-189-783）+ 保護者通知発火条件 4 段階を確立[^7][^8][^9]。
5. **アプリ内法務文言**: プライバシーポリシー雛形（13 章構成）/ 利用規約雛形（11 章構成）/ 同意文言（保護者用 + 子ども用）を v1 として整備、Phase 1 W2-W3 で実装。

### 1-3. DB スキーマ

```sql
-- 保護者
CREATE TABLE parents (
  id TEXT PRIMARY KEY,  -- UUID
  email TEXT UNIQUE NOT NULL,
  email_verified_at DATETIME,
  password_hash TEXT NOT NULL,  -- Better Auth 経由
  created_at DATETIME NOT NULL,
  deleted_at DATETIME  -- 削除権行使時
);

-- 子ども（家族プロフィール）
CREATE TABLE children (
  id TEXT PRIMARY KEY,
  parent_id TEXT NOT NULL,
  nickname TEXT NOT NULL,  -- 本名禁止のバリデーション必要（ヒューリスティック）
  grade TEXT NOT NULL,  -- '小4' | '小5' | '小6' | '中1' | '中2'
  target_eiken_level TEXT,
  exam_date DATE,
  created_at DATETIME NOT NULL,
  deleted_at DATETIME,
  FOREIGN KEY (parent_id) REFERENCES parents(id)
);

-- 同意ログ（撤回権・削除権の証跡）
CREATE TABLE consent_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_id TEXT NOT NULL,
  consent_type TEXT NOT NULL,  -- 'tos' | 'privacy' | 'child_data' | 'ai_chat' | 'cookies'
  consent_version TEXT NOT NULL,  -- 規約 / ポリシーのバージョン文字列 'v1.0.0'
  action TEXT NOT NULL,  -- 'granted' | 'revoked'
  consented_at DATETIME NOT NULL,
  ip_address TEXT,  -- 必要時のみ・90 日後ハッシュ化
  user_agent TEXT,
  FOREIGN KEY (parent_id) REFERENCES parents(id)
);

-- 削除請求
CREATE TABLE deletion_requests (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_id TEXT NOT NULL,
  child_id TEXT,  -- null = 保護者本人 + 全子ども
  requested_at DATETIME NOT NULL,
  scheduled_at DATETIME NOT NULL,  -- 法定 30 日以内
  completed_at DATETIME,
  reason TEXT,
  FOREIGN KEY (parent_id) REFERENCES parents(id)
);
```

### 1-4. 撤回権・削除権の実装

| 権利 | UI | DB 動作 | 法定期限 |
|------|------|---------|---------|
| 同意撤回（ai_chat だけ等の部分撤回） | 保護者ダッシュボード「同意設定」 | consent_logs.action='revoked' insert | 即時 |
| 全データ削除 | 保護者ダッシュボード「アカウント削除」 | deletion_requests insert + 30 日後物理削除（ジョブ） | 30 日以内 |
| 子ども 1 人だけ削除 | 子どもプロフィール画面「削除」 | child_id 指定で deletion_requests insert | 30 日以内 |
| データエクスポート | 保護者ダッシュボード「データダウンロード」 | JSON export | 30 日以内 |

## 3. AI チャット安全ポリシー（Phase 0 強化版）

### 3-1. System Prompt 必須要素（9 項目）

```
あなたは小学生（10〜13 歳）向けの英語学習コーチ「ことだまトリ」です。
英検 5 級〜3 級の合格を一緒に目指す相棒として、子どもにやさしく、はげまし、ほめながら学習を支えます。

【必須遵守事項】

1. 【ですます調 + ひらがな多め】
   - 子どもにとってやさしい言葉づかい
   - 漢字は最小限、必要な漢字には文脈で意味を示す

2. 【絶対に出さない話題】
   - 性的内容（恋愛は「すきな人いる？」レベルで止める、それ以上は不可）
   - 暴力・残虐・恐怖
   - 差別（人種・性別・国籍・宗教・障害）
   - 自殺・自傷・薬物・賭博・酒・タバコ
   - 政治的論争・宗教論争
   - ロールプレイ依頼（OpenAI 16 歳未満ガイダンス準拠）

3. 【個人情報を聞かない / 保存しない】
   - 本名・住所・電話番号・学校名・SNS アカウントを聞かない
   - 子どもが教えてくれても保存せず、「英語の話にもどろう」で受け流す

4. 【危機検知時の即時対応】（§3-2 参照）
   - 自殺・自傷・虐待・いじめ・性的被害を示唆する発話は即座に検知
   - 「とてもつらいきもちなんだね。おうちの人や先生に話してみよう」+ 189（児童相談所）案内
   - それ以上踏み込まず、英語学習に戻さない（深追い禁止）

5. 【英語以外の深掘り禁止】
   - 恋愛・家族・友達トラブルは「それはおうちの人に話してみてね」で止める
   - 英語学習に関係する話題のみ深く対応

6. 【嘘・推測の断定禁止】
   - 不確実な情報は「先生に確認してね」「あとで調べてみるね」を使う
   - 英検仕様の不明点は「公式サイトを見てみよう」で逃げる

7. 【絵文字・カジュアル過ぎる表現禁止】
   - UI 規約に準拠（Heroicons / shadcn のみ）
   - 「！」「？」は OK だが「！！！！」のような過剰反復禁止

8. 【出力長制限】
   - 1 回の応答は 200 字以内（子どもの集中力配慮）
   - 解説モードは 400 字まで OK

9. 【自分が AI であることの透明性】
   - 「ぼくは AI のことだまトリだよ」と聞かれたら肯定する
   - 「人間の先生」を装わない（UNICEF 透明性原則）
```

### 3-4. 保護者通知の発火条件（4 段階）

| レベル | 条件 | 通知方法 | 例 |
|-------|------|----------|---|
| **L1: 軽度フラグ** | Moderation で sexual/violence/hate のスコア 0.3-0.5 | 保護者ダッシュボードに表示（即時通知なし） | 「ばか」「うざい」レベル |
| **L2: 中度フラグ** | Moderation スコア 0.5-0.8 + 危機検知ワード 1 件 | 保護者にメール通知（24 時間以内） | 「いじめられて」 |
| **L3: 重度フラグ** | Moderation スコア 0.8 以上 + 危機検知ワード 2 件以上 | 保護者にメール + アプリ内 push 即時通知 | 「死にたい」「殴られた」 |
| **L4: 緊急** | 自殺・暴力被害の具体的計画・状況の言及 | 保護者にメール + push + AI コーチが即時 189 案内 | 「いまから飛び降りる」等 |

### 3-5. 三重ガードのフロー

```
[ユーザー入力（子どもからの textarea 入力）]
  ↓
[① OpenAI Moderation API] - violence/sexual/hate/self-harm/sexual-minors を 0.0-1.0 スコア化
  ↓ scores 確認
  ↓ 危機検知ワード正規表現マッチ → L1-L4 判定
  ↓
  L3-L4 の場合: 即座に AI 応答せず「先生」モード固定応答 + 保護者通知ジョブ
  L1-L2 の場合: 通常フローに進む
  ↓
[② System Prompt + RAG（社内ナレッジ）]
  ↓
[gpt-5-mini]
  ↓
[③ OpenAI Moderation API（出力に対しても再走査）]
  ↓ scores 確認
  ↓ 出力に sexual/violence の含意があれば再生成 1 回 → 失敗で「英語の話にもどろう」固定応答
  ↓
[ユーザー表示]
```

## 5. 結論 & 上申

### 5-1. Phase 1 W2-W3 で実装すべきもの

1. **保護者サインアップ → メール認証 → 子ども追加 → 同意確認**の 4 ステップフロー
2. **DB スキーマ**: `parents` / `children` / `consent_logs` / `deletion_requests`（§1-3）
3. **AI チャット三重ガード**: Moderation 入力 → System prompt → Moderation 出力（§3-5）
4. **危機検知**: 60 語ワードリスト + L1-L4 判定 + 保護者通知ジョブ（§3-2 ～ §3-4）
5. **保護者ダッシュボード**: 同意管理 / チャット履歴閲覧 / アカウント削除 / データエクスポート

### 5-2. Phase 1 W4-W5 で実装すべきもの

1. **プライバシーポリシー / 利用規約 / 同意文言**を `/legal/*` ルートで公開（§4）
2. **削除請求の 30 日 SLA バッチ**（Trigger.dev v3）
3. **同意撤回 UI**（部分撤回対応）

### 5-3. Phase 2 / Phase 3 検討事項

- **COPPA 準拠**（海外展開時）: SMS / KBA / 顔認証 ID 比較の 3 種同意確認手段[^4]
- **書面化された情報セキュリティプログラム**（COPPA 改正必須[^4]）の docs 化

### 5-4. オーナー上申事項（軽承認候補）

1. **【法的根拠】** 改正個情法（令和8年改正）が施行前でも先行 16 歳未満対応で実装する方針 → 推奨（GDPR 整合・将来手戻り回避）
2. **【プライバシーポリシー文言】** §4-1 雛形を Phase 1 W2-W3 で実装 → 弁護士レビュー予算（任意・無料運用方針なら個人事業主レベルで自社確認も可）

### 5-5. リスク

| # | リスク | 影響 | 対応 |
|---|--------|-----|------|
| LR-1 | 改正個情法の最終条文が変わる | 中 | 2026 通常国会の最終条文を W6 で再確認、必要なら DEC 追加 |
| LR-2 | 危機検知ワードリストの抜け漏れ | 大 | β中に学習者のフィードバックで追加、月次レビュー |
| LR-3 | AI 応答の安全フィルタすり抜け | 致命 | 三重ガード + 監視ログ + 月次サンプリング 100 件人手レビュー |
| LR-4 | 保護者通知の遅延 | 大 | L3-L4 は同期送信（メール + push 即時）、L1-L2 のみ非同期キュー |
| LR-5 | 海外展開時の COPPA 違反 | 大 | Phase 2/3 で SMS/KBA 等を実装、Phase 1 では「日本国内限定」明記 |
