## 1. 総合判定

### 判定: **CONDITIONAL GO**（条件付きで Phase 1 W1 着手を許可）

### 判定理由（一行要約）

5レポート個別の品質はいずれも極めて高く、真のゴール「半年で英検3級合格」の達成可能性も論理的に裏付けされている。**ただし 5レポート間で「技術スタックの根幹」「問題プール規模」「W4/W8/W10 の品質ゲート KPI」「課金モデル」の4点が整合していない**。これらを W1 着手前にオーナー決裁＋ decisions.md 記録で確定させれば Go、未確定のまま着手すると W4 中間レビュー以降に手戻りが必発する。

## 3. 真のゴール（半年で英検3級合格）達成リスク評価

### 3.1 真のゴール達成のための4要素チェック

| 要素 | 必要条件 | 5レポートで担保されているか | 評価 |
|------|---------|---------------------------|------|
| **学習時間** | 180時間（毎日1時間×180日） | research が文献根拠（200-300h目安）と整合確認、pm が「Day1-180 配分」明示 | A |
| **学習内容（カリキュラム）** | 5級→4級→3級の段階的合格、語彙2,100語 / 文法 / 4技能 | pm の WBS 5、marketing の段階別目標、research の §1（一次情報）整合 | A |
| **適応学習エンジン** | 本人レベル推定 + 弱点重点 + SRS | research = FSRS + IRT + BKT、dev = ts-fsrs + BKT 1PL Rasch、pm = SM-2簡易（Phase 1）→ FSRS（Phase 2） | **B-（pm と dev で SRS 採用版の乖離）** |
| **AIコーチ品質** | 誤答解説・Q&A・小学生向け語彙 | research・pm・dev で三重ガード + 小学生向け言い換え合意、dev で tool use 4関数 + System Prompt 設計済 | A |
| **継続装置（ゲーミフィケーション）** | streak / レベル / バッジ / キャラ | design・pm・dev で MUST 機能合意、design で「自己肯定感マイクロコピー指針」明文化 | A |
| **問題プール量・質** | 5,000〜6,000問の自社オリジナル問題 | research = 6,000問・¥50万人手検収 / pm = 1,600問・4人日 / dev = 9,000問 | **C（規模未確定 + pm の人日見積りが過小）** |
| **学習者の現状起点** | 「ゼロスタート」or「4級経由」のターゲット定義 | research が「ゼロスタートは7-8か月、4級経由なら半年が安全圏」と警告、pm は「初期診断テストで現在地確定」だが訴求は未定、marketing は「半年で英検3級」と言い切る | **C+（訴求と内部設計の乖離）** |

### 3.2 真のゴール達成リスクのトップ3

#### R1（致命）: 「ゼロスタート小6で半年で3級」のマーケ訴求が研究結論と矛盾

- **研究結論**: 「ゼロスタートは200-300時間（7-10か月）、半年は最短ライン。4級合格者からなら半年で3級は十分到達可能」（research §2-2）
- **マーケ訴求**: 「半年で英検3級。AIコーチが毎日伴走。」「合格率70%以上」「半年合格保証」
- **PMの内部目標**: 「β10名で5名以上 = 50%」
- **乖離**: 70%（marketing）と 50%（pm）の差は小さくない。research は「合格を目指す」「合格できる」のどちらを採るか上申に出している
- **未対応リスク**: ゼロスタートの子が落ちた場合、保証返金（marketing 5.3）が連発し、CACが赤字化

#### R2（大）: 問題プール規模・人日見積りの乖離が W4 中間レビューを直撃

- pm の WBS 4.3 = 1,600問 を 4人日で AI生成+人手レビュー
- research = 6,000問 で **人手検収 ¥50万 + AI生成 ¥1,500**
- dev = 「3,000問/レベル × 3 = 9,000問」を `seed-problems.ts` で一次生成
- **pm の 4人日見積りは research の人手検収50万円との乖離が極端**。1,600問 × 2分/問 = 3,200分 ≒ 53時間 ≒ 6.6人日（1日8h換算）であり、**ベンチマーク的にも過小**
- W4 中間レビューで「問題プール50%（800問）」が達成できないと、W5以降の学習コアループ実装でテストデータが不足し玉突き遅延

#### R3（中）: 「半年合格保証キャンペーン」と Phase 1 設計の不整合

- marketing 5.3 = 公開β移行時に「3か月分返金 or 延長」発動
- pm の Phase 1 リリースゲート（W10）= 「クローズドβ開始」
- pm の Phase 2 想定 = 公開β移行
- **保証キャンペーンの「合格保証対象条件（学習行動データ + 模試合格ライン）」を Phase 1 のデータモデルで取得できるか**が dev では具体に落ちていない（mock_exam_results は dev の ER 図に存在するが、保証発動ロジックは設計外）

### 3.3 達成可能性総合評価: **B+（条件付き）**

「4級レベル経験者なら確実、ゼロスタート小6なら最短ライン」が研究の結論。Phase 1 MVP の設計品質は高く、適応学習・AIコーチ・継続装置の3要素は十分に到達可能性を支える。**ただし「ゼロスタート小6にも訴求する」ならマーケコピーを「合格を目指す」に補正**するか、**pm の50%と marketing の70%の差を埋めるβ計測設計**が必要。

### 4.2 5レポート横断で揃っている部分（このまま採用可）

1. **AI生成100%オリジナル問題 + 人手検収パイプライン**（過去問流用禁止）

## 5. 重大リスクと改善要求（優先順位 P0/P1/P2）

### 5.1 P0（W1 着手前に必ず解消・CEO/オーナー決裁要）

#### P0-1: DB / Auth / Storage の根幹スタック不整合

- **指摘**: research・pm = Supabase 前提 / dev = Turso + Better Auth + R2 を独自推奨
- **影響**: pm の WBS 1.3「Supabase プロジェクト作成」「RLS 雛形」が dev 設計と衝突。schema 自体が SQL flavor（PostgreSQL vs SQLite）から違う。**着手後の手戻りが最大3週間**
- **改善要求**:
  - **CEO/オーナーが「Turso + Better Auth + R2」採用 or 「Supabase 統合」採用を確定**
  - 採用案を `decisions.md` に記録（理由・コスト試算・組織標準との整合）
  - **レビュー部門推奨**: 個人開発・無料運用維持の最優先制約と egress 無料の決定打を踏まえ、**Turso + Better Auth + R2** を支持。ただし dev の POC-1（Better Auth + Turso + 児童アカウント運用）が W1 で必須

#### P0-2: AI モデル選定（gpt-5-mini vs gpt-4.1-mini）

- **指摘**: research = 「gpt-5-mini は 2025-08-07 リリース済み」と一次情報で明言 / dev = 「2026-04 時点で API 一般公開未確定」と異なる前提
- **影響**: コスト試算（research ¥65/人/月 vs dev $5.2/100名・月）の根拠が違う
- **改善要求**:
  - W1 着手前に research 部門が **gpt-5-mini を実 API キーで疎通確認**（応答時間・コスト・Structured Outputs 対応）
  - 結果を decisions.md に記録、dev の §1.1 / §4.1 を更新
  - フォールバックは AI SDK の provider 抽象化で gpt-4.1-mini / gpt-4o-mini に切替可能とする（dev の設計通り）

#### P0-3: 問題プール規模・人日見積りの3レポート乖離

- **指摘**: research = 6,000問 / pm = 1,600問・4人日 / dev = 9,000問
- **影響**: pm の 4.3 タスク 4人日見積りが現実不能。W4 中間レビューで縮退判定を強いられる確率高
- **改善要求**:
  - **Phase 1 で投入する問題数を 5級400問 / 4級500問 / 3級700問 = 1,600問**（pm 案）に確定
  - ただし人日は **research の試算を採用し、AI生成 + 人手検収（外注）を含めて Phase 1 中の累計 ¥30〜50万を別予算化**
  - WBS 4.3 を 4人日 → **人手検収を外注前提で 2人日（管理工数のみ）+ ¥30万予算** に修正
  - Phase 2 で 5,000問規模に拡張する計画を decisions.md に明記

#### P0-4: マーケ訴求と内部目標の乖離（合格率 70% vs 50%）

- **指摘**: marketing「合格率70%」「半年合格保証」と pm「β10名で5名 = 50%」の乖離
- **影響**: 保証発動コストが赤字化、または訴求が誇大広告化
- **改善要求**:
  - **CEO/オーナーが「半年で英検3級合格を目指す」（推奨：research 案）か「合格できる/合格保証」を確定**
  - β中の合格率実績で「合格者の声」を蓄積し、**Phase 2 公開β以降に保証条項を発動**（marketing 5.3 のスケジュールと整合）
  - pm の β規模を **5〜10名 → 30〜50家庭（marketing と一致）** に修正、または marketing が β規模を pm に揃える

#### P0-5: 月額運用コスト試算の20倍乖離

- **指摘**: research ¥24,000/月（100名）vs dev ¥1,200/月（定常運用）
- **影響**: Vercel Hobby の商用禁止条項（research §9-1 で明示）を dev が看過
- **改善要求**:

  - **公開β / 有料化（marketing の¥1,980プラン投入）の瞬間に Vercel Pro $20 へ移行**を decisions.md に明記
  - dev の月額試算を「Hobby（β期間限定）」「Pro（公開β以降）」の2段階に分けて再提出

#### P0-6: 命名・メインカラーの乖離

- **指摘**: marketing「HANEI / ターコイズ #2EC4B6」 vs design「ことだま英語 / Amber Gold #F2A93A」
